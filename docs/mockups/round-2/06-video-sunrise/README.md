# 06 — Video and sunrise

Seven reviewed, generated PNG design frames for the “one night in the studio” homepage. No production files were changed. Art direction: painted night as the base, ink/manga as an accent, then a return to the banner’s butter-yellow paper.

## Files and implementation notes

### 01-video-cinema-desktop-facade.png
1672 × 941. The 04:00 open-air cinema facade uses the supplied project thumbnail as a reference, projected from the cliff laptop into the sky, with a small owner mascot watching.
On click or keyboard activation, replace a real thumbnail button with a 16:9 YouTube iframe; the light beam may gently brighten on focus/hover, with no iframe or YouTube request before activation. Build with responsive image layers, an external SVG watercolor edge and a CSS/SVG beam; estimated 6–10 engineering hours for the shared cinema scene and accessible facade, excluding final asset separation.

### 02-video-cinema-desktop-playing.png
1672 × 941. The same scene after activation: central play control disappears, a plausible illustrative talking-head frame occupies the sky, and playback controls appear.
Create the iframe only on explicit activation and keep its real viewport rectangular with all decorative paint outside; soften nearby stars and the beam while preserving keyboard focus and fullscreen access. CSS handles this state without Threlte; allow another 2–4 hours for player integration, focus handling, fallback link and testing.

### 03-video-cinema-mobile-facade.png
852 × 1846, approximately 9:19.5. The mobile scene gives the 16:9 thumbnail almost the whole width and puts the projecting laptop and mascot beneath it.
Use a separately composed mobile background rather than shrinking the desktop, and swap the facade for an inline iframe in exactly the same reserved space on tap. Responsive CSS with an SVG beam and at least 44 × 44 CSS pixel targets should take 3–5 additional hours; disable decorative motion for reduced-motion visitors.

### 04-video-next-episode-desktop.png
1672 × 941. An alternate 04:00 title card combines a large placeholder episode number, dramatic title typography, ink speed lines and the same project thumbnail.
A single short ink reveal on entry could establish the accent, while the play action uses the same accessible facade component; the speed lines must remain still after the reveal. Use a raster ink texture with SVG masking and real Geist DOM text, not WebGL; estimated 4–6 additional hours and no heavy dependency.

### 05-sunrise-footer-desktop.png
1672 × 941. At 06:00 the dark sky becomes butter-yellow pigment paper, with steaming coffee, a walking owner mascot carrying a plain yellow laptop, and quiet legal/contact/social navigation.
Give the steam a slow, small opacity/translate loop while in view and optionally move the mascot a few pixels once as the footer enters; the full composition works still. Use layered painted assets, SVG steam and semantic HTML links; estimated 5–8 hours for the shared footer scene, with Threlte unnecessary.

### 06-sunrise-footer-mobile.png
831 × 1891. The mobile footer keeps the night-to-paper edge, coffee and mascot, then puts the legal links on spacious individual lines above the social row.
Use this portrait composition as an art-directed source and keep navigation as live text in normal document flow, including room for translated labels and larger text. Responsive CSS and the shared SVG steam add approximately 2–4 hours; avoid carrying the desktop footer’s horizontal link arrangement onto phones.

### 07-night-to-sunrise-mid-scroll.png
1672 × 941. One viewport midway through the transition: the video leaves the top, deep night persists above a ragged watercolor boundary, and the dawn path enters below.
Tie only a modest mask/opacity shift to scroll position, never hijack scrolling, and keep the organic pigment boundary present even with motion disabled. Two overlapping painted layers with an SVG alpha mask and progressive CSS scroll animation should take 3–5 hours; a static boundary is the baseline fallback.

## Production boundaries

- These are image mockups, not functioning players or final shipped copy. All TODO(copy) labels must be replaced with copy generated by gpt-6.1-sol through Paraglide; the placeholder episode number must come from real metadata.
- The supplied thumbnail was used as an image-generation reference and is visually interpreted in these PNGs. Production must use the original `08-buttergelb-thumbnail-projekt-youtube-1280x720.jpg` unchanged inside a reserved `aspect-ratio: 16 / 9` area. Do not reproduce the generated facade’s slight painted perspective on the actual iframe.
- The playing image is a synthetic illustrative frame, not a captured video or an assertion about the newest upload. Resolve the real video ID and title through the site’s cached data layer; no video ID was invented.
- Use the real owner-approved navigation destinations. Legal link labels are shown, but no legal copy was generated.
- The PNGs total about 18.7 MiB and are design masters, not appropriate production downloads. Export art-directed AVIF/WebP layers; a rough target is 250–600 KiB per desktop scene and 150–350 KiB per mobile scene, subject to visual checks. Share paper/noise textures and lazy-load below-the-fold art; YouTube’s third-party payload is separate and begins only on click.
- Estimate roughly 25–42 engineering hours for the main cinema, footer and transition together, plus 4–6 hours for the optional manga variant. These are planning estimates, not measured implementation or rendering costs; final layer extraction and any new illustration work are extra.
- No Three.js/Threlte runtime is required for this direction. If depth is later desired, use a separately approved, lazily loaded handful of watercolor planes, with the static artwork as fallback.
- Review covered text legibility, palette continuity, character anatomy and unwanted marks. One rejected sunrise source remains in `rejects/`; a second corrective generation replaced its unwanted laptop mark with a plain yellow lid.
- `PROMPTS.md` records exact prompts, input references and both correction prompts.
