# Performance audit, November 2026

Audit only: no source file was changed. Every proposal below is meant to be invisible: same art, same animations, same quality. Measured on 2026-11-09 against the live site. The live site serves the exact build of `main` @ `8738a17`, with the same chunk hashes as a local `pnpm build`.

## Summary

The old phone feels slow for three reasons, roughly in this order:

1. **The main thread never rests.** On a 6× throttled CPU, the homepage keeps the main thread **~40–50 % busy while the visitor does nothing**. /stats is at **~55–65 %** and /blog at **~30 %**. The cause is not drawing. Two things make the browser produce a main-thread frame on every vsync (60 Hz):
   - `RafLoop` requests `requestAnimationFrame` every vsync, even for loops capped at 20 or 30 fps, and the hero parallax loop runs on touch devices where it does nothing.
   - Three hero CSS animations cannot run on the compositor.

   Each of those frames also re-runs style for every running CSS animation. Simulating the fixes cut idle cost by **72–78 %** on all three pages.

2. **Hydration waits for the error page.** SvelteKit imports the root `+error.svelte` node before it hydrates any page. That node is 13.6 kB of JS plus 6.7 kB of CSS (the giant wall and world tree art), and it is fetched late, as a waterfall. Every page hydrates **0.6–2 s later** than it could on slow 4G.
3. **Bandwidth goes to things nobody sees yet.**
   - About 450 kB of below-the-fold homepage images download in parallel with the moon (the LCP image).
   - /kontakt starts Turnstile on mount and keeps the CPU busy for over 30 s.
   - CSS background washes ship as WebP at 3–7× the size of their AVIF siblings.
   - /stats downloads the full 70 kB Geist Mono for a single arrow glyph.

None of the proposed fixes changes art, animation timing or image quality. Two need a side-by-side visual check: the AVIF washes (encoder change) and the deferred below-the-fold images (load timing).

Radio audio is confirmed lazy: no audio request happens on load or after scrolling the whole page.

## Method

- **Browser.** Headless Chrome 156 driven over raw CDP with Node's built-in WebSocket. No new packages; Lighthouse was not used. Tools are in `docs/perf/tools/` (see [Re-running](#re-running)).
- **Profile.**
  - Phone viewport 412×823 at DPR 2.625, touch on, Android user agent.
  - **CPU throttled 6×.**
  - **Slow 4G** (Lighthouse mobile: 150 ms RTT, 1.6 Mbit/s down, 750 kbit/s up).
  - Cache disabled.
  - The machine's OS is in dark mode, so the site rendered its dark theme.
- **Per run.** Navigation timing, FCP and LCP (with element), CLS, long tasks, Long Animation Frames (with script attribution), every request (priority, timing, transferred bytes), and `Performance.getMetrics` deltas.
- **Idle cost.** Main-thread task/style/script ms per second while sitting at the top of the page after the network went quiet. Experiments:
  - pause CSS animations one at a time;
  - block rAF;
  - throttle rAF to about 22 Hz.

  A trace extracted Chrome's compositor-failure reasons per animation.

- **Builds.** `pnpm build` for payload sizes, and a `--sourcemap` build to map chunks to modules.
- **Code review.** A source review of `src/lib/**` ran in parallel. Its claims that were not measured are listed under [Speculative](#speculative-measure-before-committing).
- **Caveats.**
  - Headless desktop GPU ≠ Mali GPU, so raster and composite costs on the phone are higher than measured here.
  - Absolute timings vary ±15 % between runs. The numbers below are medians where several runs exist (homepage n=10, /stats n=3, /blog n=2, others n=1).

### Checked and fine

- **Caching.**
  - `/_app/immutable/*`: `public, immutable, max-age=31536000`, Brotli.
  - Fonts: 30 days. `/media/*`: 7 days.
  - Prerendered HTML: `max-age=0, must-revalidate`, served from the edge (`CF-Cache-Status: REVALIDATED`, TTFB 44–350 ms).
  - `/stats`: `max-age=600, s-maxage=3600` (Workers Cache).
  - HTTP/3 is advertised.
  - Nothing to gain for an uncached first visit. The only cache item is the new font filename in #6.
- **Fonts.** `font-display: swap`; Latin subsets preloaded; Mono at `fetchpriority=low`. No CLS: 0.000 on every page.
- **Images.**
  - Hero `fetchpriority=high` on the LCP moon.
  - Decoded sizes are consistent with the displayed sizes. The moon picks the 1942 px file for a 1078 CSS px box at DPR 2.6, which is not oversized.
  - `hero-sky-mobile` decodes at 412×892 for a 428×872 box.
  - LCP per page:

    | Page     | LCP element               | Time  |
    | -------- | ------------------------- | ----- |
    | `/`      | moon `<img>`              | 6.0 s |
    | /blog    | H1 text                   | 2.4 s |
    | /kontakt | H1 text                   | 2.4 s |
    | /stats   | `stats-hill-feather.webp` | 3.1 s |
    | post     | CSS wash (see #5)         | 3.4 s |
- **Heavy chunks stay lazy.**
  - three/Threlte (`UolkoufM.js`, 767 kB raw) is never requested on the phone, even after a full scroll.
  - The game engines (`tJHCEhin`, `CwnW3y44`, `DzE-JkOD`), the eggs, the bits-ui menus (`C-0cMa3D`, 100 kB raw) and the post bodies are all separate dynamic chunks, absent from the modulepreloads.
- **Audio.**
  - Track URLs are string-only (`track/index.ts:32`, `?url`).
  - `<audio preload="none">` has no `src` until `select()` runs from a key or dial gesture (`Radio.svelte:58-85`, `:248-256`).
  - `sound.ts` generates its noise in code.
  - No audio request was observed on load or after scrolling the whole page.
- **YouTube.** Self-hosted thumbnails. The iframe only appears after the consent click (Cinema and VideoFacade).
- **Reduced motion.** With `prefers-reduced-motion: reduce`, homepage idle cost is **1 ms/s**. That confirms the idle cost is entirely animation-driven.

## Suggested order

## Re-running

The tools in `docs/perf/tools/` use only Node built-ins and the installed Chrome.

```sh
pnpm build && node docs/perf/tools/payload.mjs .svelte-kit/cloudflare index.html blog.html kontakt.html impressum.html blog/meine-website-mit-ai-agenten.html
node docs/perf/tools/cdp-run.mjs https://solo-stack.dev/ out/home --idle 8000            # load + idle cost
node docs/perf/tools/cdp-run.mjs https://solo-stack.dev/stats out/stats --experiments    # + per-animation / rAF A/B
node docs/perf/tools/cdp-run.mjs https://solo-stack.dev/ out/home-s --scroll             # + full-page touch scroll
node docs/perf/tools/cdp-run.mjs https://solo-stack.dev/ out/home-t --trace              # + Chrome trace (out/home-t.trace.json)
node docs/perf/tools/sum.mjs out/home.json out/stats.json                                 # summary
node docs/perf/tools/trace-agg.mjs out/home-t.trace.json 10000 17000                      # self time by thread/event in a window (ms)
```

Other `cdp-run.mjs` flags:

- `--cpu <rate>` (default 6)
- `--no-throttle-net`
- `--reduced`
- `--profile` (CPU profile of the idle phase; read it with `prof-agg.mjs`)
- `--raf-throttle <ms>` (simulates fix #1)
- `--pause-anim a,b` (pauses the named CSS animations before the idle phase)
- `--gestures <n>`
- `--eval <expr>`

To test before a deploy, run `pnpm preview` and point the tool at `http://localhost:8787`. `wrangler dev` does not compress like the edge does, so compare compressed byte counts from `payload.mjs`, not network timings.
